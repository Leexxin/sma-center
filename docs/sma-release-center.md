# SMA 版本中心

新增日期：2026-10-16。入口：工作台侧栏“SMA 版本中心”，路径 `/sma/releases`；页面和 `/api/sma/releases` 均要求已绑定 TOTP 并登录。

## 范围

GitHub `Leexxin/server-monitor-agent` 的已发布 Release 是权威源，SFTPGo 公共分享目录是内网镜像。支持稳定版和预览版，手动选择版本、核对附件、补齐缺失文件，并在明确同意后替换冲突附件。不修改 GitHub，不删除本地额外文件，不自动安装 Agent，不执行展示的命令，不周期性后台同步。

“两边仓库”在这里指 Release 附件与文件服务器的对齐，不是 Git 分支、源码提交或双向冲突合并。GitHub 自动生成的 source.zip/source.tar.gz 不是 Release assets，不属于同步范围。

## 版本目录布局

分享链接已经指向文件服务器的 `sma-releases` 目录，该目录就是镜像根目录，不再额外建立一层 sma-releases。每个 Release 使用 GitHub 标签原样建立一个独立文件夹：

```text
分享根目录（sma-releases）/
├── v0.2.4/
│   ├── install-sma.sh
│   ├── checksums.txt
│   ├── latest.txt
│   └── sma_0.2.4_linux_amd64.deb …
├── windows-v0.3.1-rc.1/
│   ├── checksums-windows.txt
│   └── sma_0.3.1-rc.1_windows_amd64.msi …
└── v0.2.3/ …
```

比对、下载、覆盖和回读校验都限定在所选 `/<tag>/` 内；根目录或其他版本同名文件不参与判断。不会向根目录写脚本、清单或 latest.txt，不创建跨版本的 latest 别名。同步历史版本不会改变其他版本的文件。

仅核对不会创建目录。目录不存在时所有附件显示缺失；同步第一个已通过源摘要校验的附件时，使用 SFTPGo 的 mkdir_parents 创建版本目录。根目录存在与标签同名的普通文件时停止，不删除或覆盖它。旧平铺模式的核对结果会在升级时失效，必须按版本目录重新核对；历史任务仅作记录，不表示新布局已经同步。

回滚旧镜像会恢复旧根目录同步逻辑，不能再使用其旧同步按钮，否则可能重新写入根目录。版本目录数据不会自动删除或降级；重新上线新布局后先重新核对。

## 首次配置与使用

1. 进入版本中心，展开配置，填写 SFTPGo 公共分享的 upload 或 browse 完整地址，保存。不要填登录后台、API 管理入口或带密码的 URL。
2. 分享必须同时允许列举、下载和上传，且 sma-center 容器能访问。过期、密码保护或只有上传权限的分享不能完成内容核对。
3. 点击“刷新 GitHub”，选择实际发布版本。默认优先选稳定版，不假定 Windows 预览版等于 Linux 稳定版。
4. 点击“核对两边仓库”，确认页面显示目标 `/<tag>/`，等待 SHA-256 计算完成。此操作不上传、建目录或改动文件服务器，但会读取该版本目录内同名文件的完整内容，产生内网流量。
5. 查看每个附件：缺失、SHA-256 一致、内容冲突或缺少摘要。核对不以文件名和大小相同代替内容一致。
6. 若有冲突，先审查附件和发布说明；确需覆盖时勾选“允许替换”。没有勾选则不会写入任何冲突版本附件。切换版本会清除该勾选。
7. 点击“同步所选版本”，不存在的版本目录会自动建立。任务在服务端执行，可刷新页面继续看进度和最近 20 条任务记录。同步期间可以切换版本、阅读发布说明和安装文档，任务面板始终标明实际执行的标签；配置、刷新源列表、核对、再次同步及覆盖确认保持锁定。核对结果有效期 10 分钟；任务开始前还会重新读取 Release 和对应版本目录。
8. 结束后应确认全部附件一致，而非只看请求已返回。重复同步会跳过一致文件。

上传遵循 SFTPGo 分享页实际协议：先取短期 CSRF/会话，再上传原始二进制正文；令牌不保存到日志或 Git。空分享目录的 upload → browse 跳转只在同源、同分享内跟随并保留会话，不跟随登录页或其他主机。GitHub 下载不会携带文件服务器的 Cookie 或 CSRF。

## 发布顺序与风险

- 普通安装包/脚本先上传，校验文件随后，当前版本目录内的 Linux `latest.txt` 最后写入。上传前依据 GitHub 的 SHA-256 验证，上传后从同一版本目录重新下载计算摘要；任一环节失败即停止领取后续文件，等待在途文件结束后标记失败，不再发布后续校验清单或索引。普通附件最多并发两个；校验文件组在普通附件全部成功后执行，`latest.txt` 在前两组全部成功后执行。新目录的首个文件串行创建目录。
- 有附件没有 GitHub SHA-256 时拒绝自动同步，不宣称已校验。单文件最大 64 MiB，每个 Release 最多 100 个附件；超限需人工处理或修改经测试的限制。
- 同名脚本、校验清单和 `latest.txt` 按版本隔离，不再共享文件名。允许覆盖只作用于所选版本目录；不回退其他版本的安装源。
- Windows Release 只同步它实际提供的附件，不会额外生成或修改 Linux `latest.txt`。
- 分享接口没有提供本功能可用的多文件事务/CAS。本功能不是原子发布，不能防止其他用户同时上传。发布时避免并发修改；如果部分文件已经上传后失败，旧文件不会自动回滚，应重新核对、重试或人工恢复。`latest.txt` 最后更新降低风险，但不等于零中断切换。
- 不删除本地历史安装包、额外文件或未知目录。不提供自动清理或反向发布功能。
- 元数据和分享页面请求有 60 秒超时；二进制附件下载、上传和回读允许 10 分钟，避免较大安装包在慢链路上被过早中断，仍保留大小上限。界面按文件区分下载、源 SHA-256 校验、上传、回读校验，展示字节数、采样速度、源/镜像校验结果和各阶段耗时。上传字节表示 HTTP 客户端已消费的请求正文，不等于服务器已落盘；只有收到 201 且回读摘要一致才算完成。15 秒没有字节进展提示等待网络/服务器，3 秒无新字节速度归零；状态轮询超过 10 秒未成功提示重连，不把连接失败当成任务失败。状态轮询串行，避免请求堆积。GitHub API 最多读取 1000 个已发布条目所在分页，未完整读取时拒绝更新列表。GitHub 限流应稍后重试，避免连续刷新。

## 同步性能与验证边界

每次同步开始仍完整核对目标同名文件，不复用上一任务的摘要。任务内已核对一致及上传后回读一致的文件，在末尾重新列目录检查类型、存在性和大小，复用本次实际计算的 SHA-256，减少末尾重复下载。空目标新增文件只回读一次；已一致文件每次同步只完整读取一次。回读采用流式摘要，不缓存完整文件；GitHub 源文件仍完整下载并校验后上传，最多同时保留两个附件正文（单文件上限仍为 64 MiB）。

摘要复用不是 CAS/原子快照：外部写入者在本次摘要验证后修改同名同大小文件，末尾目录检查不能识别。原来的全量复查也不能防止检查后再次修改；请保持单一发布者。完成状态表示本次已验证的摘要与末尾目录检查通过，不是持续一致性保证；需要检查外部修改时，另行点击只读核对。

生产测速需从 sma-center 实际容器进行，分别记录 GitHub 首字节/完整下载、内网上传确认、回读与摘要耗时。只读测速可读取现有已验证附件；上传必须用唯一隔离测试目录，预先确认精确清理路径，不能覆盖正式版本或重启服务。测速属于瞬时样本，不代表持续带宽。当前实现的回归测试不会向生产上传。

### 2026-11-04 实际容器分段测速

在现有 sma-center 容器（Node 22.23.3）读取 Windows v0.3.0-rc.1 的 5,668,864 字节 MSI：GitHub 完整下载 86.532 秒，首字节约 2.242 秒，平均 0.062 MiB/s；同一文件内网回读 0.109 秒，约 49.6 MiB/s，两者均通过发布摘要。此前一次 45 秒超时样本收到 4,174,229 字节，说明外网吞吐有波动。

同容器向唯一隔离测试目录上传等大小随机文件，收到 201 用时 0.040 秒（约 135.2 MiB/s）；回读 0.058 秒（约 93.2 MiB/s），内存 SHA-256 计算约 22.3 ms，摘要一致。测试文件及空目录已精确删除并确认不存在，未覆盖正式版本附件、修改同步任务或重启服务。上述吞吐含内存/系统缓存影响，不等于持续磁盘带宽。本次样本指向 GitHub 外网下载链路为主要等待来源，未进一步定位运营商、代理、出口或 GitHub CDN 中的具体一环。

以上分段测速基于原运行版本。另将新版同步模块临时载入实际容器，用独立临时状态和随机内存源完成同大小隔离文件的流式上传/回读：上传确认 67 ms、回读 75 ms、源及目标摘要均通过，测试状态和分享文件均已清理；此验证不替换运行模块，也不写真实任务状态。本次进度和并发优化尚未部署到生产，不能据此宣称新页面已在生产验收。

## 安装、使用与卸载命令

切换“安装与运维命令”，再选择 Linux 或 Windows。系统从**当前所选 Release 标签**读取原项目文档：

- Linux：`docs/automatic-installation.md`、`docs/lifecycle.md`。
- Windows：`docs/windows/README.md`。

展示 shell/PowerShell 代码块，以及表格中的完整维护命令，可折叠和复制，并可打开完整原文。另依据所选 Release 附件名及可信摘要，生成带版本目录下载 URL、SHA-256 和原生包安装命令的独立分组。Linux 可选 DEB/RPM/APK，Windows 可选 MSI；必须只选匹配系统和架构的一个包。标签不存在原文或网络不可达时提示不可用，不用 main 或其他版本内容代替。只读展示，不解析执行 Markdown/HTML，也不在服务端运行脚本。复制在内网 HTTP 浏览器中提供兼容处理；失败可手动选中复制。

**上游自动安装脚本和默认 sma-ctl upgrade 仍依赖分享根目录，不能直接用于版本目录布局。** 本功能不会修改 GitHub 附件内容以免破坏摘要。命令页隐藏不适用的 install-sma.sh、默认 sma-ctl upgrade 和旧分享根目录代码块；原文链接仍可阅读。安装或升级请使用生成的版本直链原生包命令，下载与校验失败时不得继续安装；通用 tar.gz 用户可下载对应附件并参考完整原文手动安装。不提供虚假的全局 latest 安装入口。需要恢复原自动安装体验应由上游脚本增加版本路径参数并发布新 Release，再做相应适配。

版本直链采用 `browse?path=%2F<tag>%2F<filename>`，不是把版本名拼接到分享 ID 后再加 /browse。Windows MSI 命令会检查 SHA-256 和安装器退出码，不自动重启系统；3010 表示需管理员另行安排重启。

先读原文的监听地址、管理员权限、防火墙及版本支持说明。默认回环监听不等于远程可达。Token 查看会输出凭据；更换后需同步更新 sma-center。卸载、purge、Token 重置等代码块标记风险；复制不代表允许执行。先备份配置，清理卸载可能不可恢复。HTTP 分享和同源校验不能防止链路同时被篡改，仍应使用可信网络及独立可信校验渠道。

## 持久化、备份与恢复

`/data/release-sync.json`（本地开发为 `.sma-center-data/release-sync.json`）保存版本列表、布局标识 version-folders-v1、带目录的核对结果、当前任务和最近历史。分享地址用 AES-256-GCM 加密，密钥从 `secrets.json` 的 credential 派生；状态 API 不回显分享标识。命令页仅向已登录拥有者提供必要的下载命令。旧平铺核对自动清除，但不会移动或删除文件服务器上的历史平铺文件。

该文件包含在整卷备份中，页面 JSON 备份不包含它；恢复时必须与原 secrets.json 一起恢复。不要单独删除密钥。服务重启后未结束的任务标为“已中断”，不会自动恢复上传；先重新核对再重试。任务锁在当前 Node 进程内，本实现仅支持现有单实例部署，不适合多个副本共写同一个状态文件。

可选服务端环境变量 `SMA_CENTER_GITHUB_TOKEN` 用于提高 GitHub API 限额或访问已授权仓库元数据；当前同步仓库仍固定，不提供网页仓库 URL 输入。不要把 Token 写入 compose.yaml、Git 或浏览器。使用管理员维护的容器环境注入后重建服务，并检查实际生效；普通公开仓库不要求配置。

## 验证与排障

执行 `npm test`、`npm run lint`、`npm run build`。生产构建后设置 `SMA_CENTER_BROWSER_TEST=1` 运行 `tests/release-center-browser.test.mjs`，用隔离 TOTP、模拟版本 API 和独立 Chrome 验证同步中浏览版本/文档、字节变化、断线提示及手机宽度，不读取生产认证或分享配置。`tests/release-sync.test.mjs` 使用隔离模拟服务测试摘要、冲突确认、重试幂等、字节进度、停滞提示、两路并发上限与阶段屏障、减少重复回读、失败等待在途任务、加密和任务持久化；不会写入生产文件服务器。

- 无法列举：检查分享是否过期、是否只上传、是否需要密码，以及容器网络。
- 无法获取上传令牌/403：检查分享读写权限、SFTPGo 页面协议是否变化、反向代理/会话限制；不通过禁用 CSRF 修复。
- GitHub 403/429：检查限流及 Token 权限；不要持续刷新。
- 附件缺少摘要/超过限制：本版拒绝自动写入，不关闭 SHA-256 检查绕过。
- 中断/部分上传：先排除并发发布，再重新核对，未一致时不能宣称发布完成。
- 配置无法解密：核对完整备份中的 secrets.json，不生成新密钥覆盖。
- 命令页无内容：确认标签确实包含相应平台文档；不会回退到不匹配的源码版本。
